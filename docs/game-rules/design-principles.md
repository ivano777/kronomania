# Design Principles

## 1. One Engine, Many Expressions
Physical actions, spells, cantrips, defense, and hostile effects should all use the same shared resolution language whenever possible.

## 2. Growth Has Multiple Axes
Character power is not one number.
The system separates growth into Size, Pool, Keep, and specialized exceptions through nodes.

## 3. Tier Is the Standard Pool Term
Use **Tier** for base pool progression.

## 4. Stable Size Matters
Some rules care about persistent capability rather than the current temporary state.

## 5. Stable Growth Is Compact
The normal stable track is d4, d6, d8, d10.
d2 and d12 exist only as exceptional or temporary states.

## 6. Magic Is Risk, Not Mana
True spells are limited by escalation, containment, Burnout, and recovery choices.

## 7. Burnout Must Stay Clear
- the triggering spell still resolves;
- Burnout is checked afterward;
- the Fervor cap is based on **current modified Ingenuity**, not stable Ingenuity;
- true spells are blocked by default;
- cantrips remain available;
- exceptions belong in nodes.

## 8. Defense Is Active
The system uses active defensive pools instead of passive armor-style values.

## 9. Timing and Success Are Separate
VT answers **when**.
Guard and opposition answer **whether**.

## 10. Cantrips Are Real Actions
Cantrips are safer than true spells, but still fully integrated into the action system.

## 11. Exceptions Belong in Progression
Special-case mechanics should usually come from nodes, rare items, or explicit abilities.

## 12. Documentation Should Stay Modular
Rules should be split into focused files with links between them.
